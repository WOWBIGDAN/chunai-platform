# 对接总则与业务边界

版本：`1.0.0-design` · 设计日期：2026-10-22 · 框架：NestJS。

这是一份新项目的接口设计基线。2026-10-23 已实现 NestJS + MySQL 客户端密码认证；运行说明和准确范围见 [后端启动与数据库](04-backend-auth.md)。其他业务及管理员接口仍是设计契约，OpenAPI 的 `x-implementation-status` 标注每个接口的状态。当前注册、密码登录均不使用短信验证码，短信登录及忘记密码重置暂缓。域名、支付商户、短信、模型、快递与对象存储供应商需要后续配置。

## 业务默认规则

以下是本次设计采用的产品决策，便于双方立即开始开发。它们不是已确认的运营政策；若需要改变，应同步调整 DTO、状态规则和前端提示。

| 项目 | 本次设计默认值 |
|---|---|
| 平台边界 | 健康知识、课程与实物产品服务；不包含诊断、处方、在线问诊、医生排班 |
| 内容类型 | 视频科普、图文科普、视频课程、图文课程；课程由同类型章节组成 |
| 科普 | 全部免费公开浏览；不设置付费科普 |
| 课程 | 可免费，或单独付费，或会员／单独付费二选一获得访问权 |
| 课程购买 | 一个订单买一个课程；购买成功永久授权，退款后撤销；课程下架停止新购买，已购仍能访问 |
| 专栏 | 免费内容分组，可包含四种内容；多对多关联；专栏本身不卖、不授予课程权益 |
| 会员 | 固定时长、非自动续费；只覆盖标注 MEMBER_OR_PURCHASE 的课程，并提供配置的 AI 额度；不包含实物产品 |
| 会员续期 | 从 max(当前时间, 已有有效权益段结束时间) 开始追加；各段保留成交方案快照 |
| 产品 | 实物产品，按 SKU 售卖；一期同一订单一个收货地址、一个包裹，所有未退款商品一次性发货 |
| 下单 | 支持多个产品 SKU；产品、课程、会员分别下单，不混单；一期无购物车、优惠券和营销折扣 |
| 运费 | 服务端配置并计算，默认 0 分；字段保留以支持后续收费；客户端不得传入金额 |
| 取消订单 | 仅未支付订单可取消；已支付实物订单申请售后，数字订单由管理员审核退款 |
| 支付期限 | 试算 10 分钟；订单创建后待支付 30 分钟；延迟支付到账走原路退款补偿 |
| 售后 | 客户自助产品售后；未发货仅退款，发货后退货退款；确认收货后默认 7×24h 内可申请 |
| 退货期限 | 批准后 7×24h 内提交退货物流；超时关闭申请并释放占用 |
| 数字退款 | 管理员可发起课程全额退款；会员仅支持尚未开始的未来完整权益段全额退款。已开始会员段的退费政策不在本版自助流程中 |
| 收货 | 用户主动确认；快递签收不自动代表用户确认；一期无自动收货 |
| 问答 | 登录后可用；普通用户每日默认 5 次，会员按当前生效方案额度；不支持图片提问与工具代操作 |
| 提醒 | 站内通知；订单、物流、售后、会员事件自动通知，管理员可创建站内群发任务；短信仅用于鉴权 |
| 客户隐私 | 注册不强制收集性别、性生活等敏感健康信息；管理用户页面不展示问答内容 |

如需原生 App SDK 支付、拆单／多包裹、现金提现、付费专栏、自动续费、数字产品自助售后，可作为后续版本扩展；本版本不预设这些接口已存在。

## URL、请求头与响应

```text
本地示例：http://localhost:3000/api/v1
生产占位：https://api.example.com/api/v1
管理接口：https://api.example.com/api/v1/admin/...
```

| 请求头 | 使用方式 |
|---|---|
| Content-Type | 有 JSON 请求体时为 application/json；对象存储直传和渠道回调例外 |
| Authorization | 登录接口以外的受保护接口：Bearer <accessToken> |
| Idempotency-Key | 文档标注的写接口必填；建议 UUID；相同业务意图重试用同一个值 |
| X-Request-ID | 可选，1–64 位安全字符；服务端校验后回传或自行生成；响应头和响应体一致 |
| Last-Event-ID | 仅 SSE 重连时使用，为上次消费事件序号 |

普通响应使用 JSON 的 `code/message/data/requestId/timestamp` 结构，失败额外带 `error`；[详见数据格式](02-data-models.md#统一成功结构)。HTTP 状态不全部强行转换成 200。

DELETE 使用 200 和 `data.success=true`，不返回 204。异步受理返回 202，并通过对应 GET 查询最终状态。客户端不得把“受理”视为“支付成功、退款成功或文件处理完成”。

分页固定为 `page=1&pageSize=20`，最大 100。无记录时返回 `items=[]、total=0、hasNext=false`。AI 消息使用游标分页。所有排序增加 id 作为稳定次排序键；每个接口有自己的排序白名单。日期范围为 `createdFrom` 包含、`createdTo` 不包含，要求 from < to；同一查询两端相隔最多 366 天。

`keyword` 只搜索公开标题、简介、标签或产品名称，不搜索受保护课程正文、手机号和 AI 会话。产品价格区间过滤要求存在同一个启用 SKU 满足整个区间；min 不得大于 max。产品价格排序采用最低可售 SKU 价。

JSON 数字不隐式转字符串；Body 类型严格校验。Query 的 page、金额和布尔值由专用转换规则校验，`false` 不可按 JavaScript truthy 逻辑解释成 true。重复的标量 Query 参数、未知字段和非法排序拒绝。

## 角色与登录

| 身份 | 可调用范围 | 认证 |
|---|---|---|
| 游客 | 已发布科普、产品、专栏、会员方案、课程介绍及预览章节 | 不带 token |
| 客户 | 本人资料、地址、订单、售后、通知、问答，以及已授权内容 | aud=client 的 Bearer JWT |
| 管理员 | 管理端接口与授权的素材操作 | aud=admin 的 Bearer JWT + 权限码 |
| 支付渠道 | 支付／退款通知 | 渠道原始协议验签，不使用用户 JWT |

管理员和客户账户、会话及令牌 audience 分开。普通注册请求无法提交角色字段；管理员由受控初始化流程建立。本版不提供公开创建管理员、前端修改会员状态或直接修改订单支付状态的接口。

`accessToken` 默认 15 分钟；客户 refreshToken 最长 30 天，管理员 refreshToken 最长 7 天。刷新每次轮换，只保存刷新令牌的哈希；旧令牌重放撤销该会话整条链。管理员和客户端分别调用各自 refresh 接口，不能交叉使用。

前端对同一端的刷新请求实行单飞，收到 TOKEN_EXPIRED 后至多刷新一次并重放原请求；有幂等键时必须沿用原键。401 TOKEN_INVALID 或 REFRESH_TOKEN_REUSED 直接清理对应登录状态。退出、密码重置、改密、撤销设备会话、封禁会立即使相关会话失效；不能只等待 JWT 自然过期。服务端每次请求检查会话撤销与账号状态，管理员权限调整后也立即生效。

访问公开接口可不登录；可选鉴权接口若收到无效 token，返回 401，不静默降级为游客。管理员调用客户端专属接口不会获得某个客户的身份；需要使用管理端对应接口。

本版刷新令牌通过 JSON 返回与提交，未定义 Cookie 会话。前端或 BFF 应使用对应运行环境的受保护凭证存储；不要把令牌放入 URL、日志或 SSE 查询串。如果改成 HttpOnly Cookie，需另行更新刷新与退出契约及跨站请求防护，不能在联调中隐式混用。

## 管理权限

| permission | 范围 |
|---|---|
| content:write | 全部分类（含产品分类）、四类内容、章节、专栏管理与预览 |
| media:write | 管理员素材上传、处理状态查询、未引用素材删除 |
| products:write | 产品、SKU、库存与库存流水 |
| orders:read | 用户订单与物流详情；含必要的收货联系信息，读取需审计 |
| orders:ship | 发货、未揽收单号纠错 |
| aftersales:review | 售后审核、私有凭证读取、退货验收、退款处理 |
| users:read | 脱敏用户资料、当前会员状态 |
| users:ban | 封禁与解封，不可设置用户为管理员 |
| membership:write | 会员方案与启停；不允许直接编辑用户权益 |
| notifications:write | 创建、查看站内通知投递任务 |
| audit:read | 读取脱敏管理审计 |

权限按最小职责分配。例如内容编辑一般需要 content:write 和 media:write，发货人员需要 orders:read 和 orders:ship。媒体接口可接受两种 token，管理员分支仍要检查用途及 media:write；售后凭证读取单独检查 aftersales:review 与售后关联。

全部 `/me`、订单、支付尝试、售后、地址、会话、问答、通知、上传记录查询同时限定 `ownerId=当前客户`。跨用户访问统一返回 404，避免暴露资源是否存在。管理接口无权限返回 403。仅校验“已经登录”不足以授权任何业务对象。

## 金额、幂等与并发

全部金额为整数分，币种固定 CNY。订单行 subtotal=unitPrice×quantity；订单应付=商品合计+运费。没有前端传入的优惠或退款金额。数据库用整数／定点数，序列化时检查 JavaScript 安全整数范围；ID 始终以字符串输出。

幂等键以“端类型＋主体 ID＋HTTP 方法＋实际路径＋Key”确定作用域；对规范化请求体与相关业务参数存摘要。至少保存 24 小时，保存原状态码与原响应。相同请求返回原结果，附 `Idempotency-Replayed: true` 响应头；同键不同请求返回 409 IDEMPOTENCY_CONFLICT；仍在执行返回 409 IDEMPOTENCY_IN_PROGRESS 与 Retry-After。发生无可靠结果的依赖错误时保留执行状态并查单／补偿，不能让重试绕过已发生的扣款或退款。

幂等记录过期后，业务唯一约束仍成立：一个 quote 只生成一单；一个支付交易只能入账一次；一个有效课程购买只能授权一次；同一个退款号不能二次退款；一个 AI clientMessageId 不能重复扣额度。幂等不是库存和支付事务的替代品。

管理员与需要版本控制的客户修改提交 version。版本冲突返回 409 VERSION_CONFLICT；拒绝静默覆盖。发货、支付、取消、售后与退款还需共享订单行锁或等效的原子条件更新，在同一事务中保持状态、库存、金额、权益和事件一致。

本版内部业务事件使用事务 Outbox：先把状态变化和待发送事件写入同一数据库事务，再由任务消费者投递通知、更新搜索、查询物流。消费者按 eventId 去重，失败重试，不在数据库提交前发送“支付成功”提醒。

## 媒体、缓存与外部协议

视频、付费正文、问答、售后凭证及用户资料默认私有。列表与元数据不携带源视频、完整付费正文或凭证永久 URL。内容图片须符合已发布的公开正文或封面用途；售后凭证始终私有。正文写入必须校验图片引用完整性，不能只上传图片 ID 再在 HTML 插入任意外部私有路径。

私有对象存储、CDN 鉴权及源站访问策略必须同时生效；签名播放 URL 默认 5 分钟，退款或封禁后停止签发新授权。已发出的短时 URL 可能在过期前继续有效；若业务要求立即撤销，应由媒体分发层增加会话校验。预览使用独立免费章节，不能把完整受保护视频地址发送前端后依靠播放器计时限制。

鉴权、订单、问答和授权 URL 响应使用 `Cache-Control: private, no-store`。含 access 判定的内容详情不可跨用户共享缓存。公开列表可做不包含身份信息的公共缓存，发布／下架触发失效。敏感日志清除手机号、地址细节、密码、令牌与健康问题正文。

支付回调路径使用本平台 URL，但请求体、签名头、解密和 ACK 是外部商户协议。OpenAPI 中此处明确保留为外部载荷，而不是杜撰一个所有渠道都使用的签名字段。选定渠道及商户协议后，需在适配器中落实其准确字段并以沙箱回调验收；前端无需调用这些接口。物流采用后台主动查询，不定义虚构的通用物流回调。

## NestJS 模块落地建议

| 模块 | 职责 |
|---|---|
| AuthModule / AdminAuthModule | 独立登录、令牌轮换、会话撤销、短信挑战 |
| UsersModule / AddressesModule | 本人资料、脱敏管理资料、封禁、收货地址 |
| ContentModule / ColumnsModule | 科普、课程、章节、分类、专栏、正文及访问判定 |
| ProductsModule / InventoryModule | 产品、SKU、可售库存、预占与库存调整 |
| OrdersModule / PaymentsModule | 报价、订单状态、支付尝试、渠道适配、补账 |
| ShipmentsModule / AfterSalesModule | 出库、物流快照、退货、退款 |
| MembershipModule / EntitlementsModule | 方案快照、会员权益段、课程永久购买权 |
| AiModule | 会话、消息、任务、输入输出过滤、额度与 SSE |
| NotificationsModule / MediaModule | Outbox 消费、站内通知、文件直传、转码与授权 |
| AuditModule / JobsModule | 审计、超时关闭、回调重试、查单、退款补偿 |

使用 DTO 白名单校验、统一异常映射、响应封装、独立身份 Guard、权限 Guard 和资源归属查询。统一响应封装只包普通 JSON API；SSE、渠道 ACK 和对象存储直传必须显式绕过。认证敏感接口单独限流。渠道回调保留原始 body，避免解析重排导致验签失败。

OpenAPI 文件是本版传输契约。后续 NestJS DTO 与 Swagger 生成结果应与其做差异核对；领域实体和数据库记录不能直接作为返回 DTO。框架包版本在建项时锁定，本文不依赖某个未指定的 NestJS 主版本。

## 建议的数据关系

| 关系 | 约束 |
|---|---|
| User → Session / Address / Order / Conversation / Notification | 一对多；业务查询强制 owner 条件 |
| Content → Chapter | 课程一对多；科普不创建章节；章节类型跟随课程 |
| Content ↔ Column | 多对多；关联含 sortOrder；唯一 (columnId,contentId) |
| Product → SKU → StockLedger | 一对多；SKU 编号全局唯一；onHand>=reserved>=0 |
| Order → OrderItem / PaymentAttempt / Refund | 一对多；成交快照不可改写 |
| Order → Shipment | 一期一对零或一；orderId 唯一 |
| AfterSale → AfterSaleItem / ReturnShipment / Refund | 同一订单同时最多一张活跃申请；完成后可对剩余数量再申请；同一数量不可重复占用 |
| User + Course → CourseEntitlement | 同一用户与课程最多一个 ACTIVE 独立购买权 |
| MembershipOrder → MembershipGrant | 每单一段；方案快照、起止时间、退款撤销状态可审计 |
| Conversation → Message / Generation | 同一会话最多一个活跃生成；(owner,conversation,clientMessageId) 唯一 |
| ProviderTransaction / RefundRequest / OutboxEvent | 渠道交易号、商户退款号、事件 ID 均有唯一约束 |

公开 DTO 不等于数据库表。数据库内部可增加支付凭据哈希、加密联系信息、事件重试次数、软删除时间和操作者等字段，不能因此自动向前端公开。
